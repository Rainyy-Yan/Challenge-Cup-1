# 工业机器人知识储备受控入库设计

## 目标

将已经完成机器来源审查的 `KB-027` 至 `KB-120` 共 94 条工业机器人知识切片导入当前运行库，同时保持现有 26 条正式知识、20 条在线 Demo 来源和人工核验语义不变。

## 当前基线

- 当前运行库 `data/kb/robotics.jsonl` 有 26 条记录，编号为 `KB-001` 至 `KB-026`。
- `Retriever.from_jsonl(..., demo_only=True)` 当前加载 20 条记录，且与 `data/demo_source_manifest.json` 完全一致。
- 候选工作区有 120 条记录，但落后当前主线并包含对前 26 条记录的历史改写，不能整体覆盖。
- 真正新增部分为 `KB-027` 至 `KB-120`：94 条、全部 `origin=sourced`、全部 `verified=false`，并具有知识点、来源 URL、定位信息、`REF-ID` 和 SHA-256。
- 机器审计发现旧冲突算法会把 `UR30`、`YRC1000`、`IRC5` 等适用机型误当成定义对象，产生大量伪冲突。

## 采用方案

### 1. 仅追加，不覆盖

保持 `KB-001` 至 `KB-026` 的当前主线内容逐字不变，只从候选资料中提取 `KB-027` 至 `KB-120`。不迁移候选工作区的业务代码、前测题、模型配置、报告文件或其他未提交改动。

### 2. 新增资料默认进入储备区

每条新增记录必须满足：

- `origin` 为 `sourced`；
- `verified` 为 `false`；
- `demo_eligible` 为 `false`；
- `id` 连续且不得与现有编号重复；
- `kp` 必须属于 `data/knowledge_points.json`；
- `source` 必须含 `REF-ID`、HTTPS URL、定位文本和 64 位 SHA-256。

因此普通检索和离线研究工具可以读取 120 条资料，正式服务器和在线编排器仍只读取原有 20 条 Demo 来源。后续只有完成人工来源复核、更新 Demo 来源清单并单独通过评审，才能将某条储备记录设为 `demo_eligible=true`；机器审计不得自动完成这一提升。

### 3. 审计规则兼容当前资料语义

审计器保留现有的孤儿知识点、来源、重复、数字冲突和定义冲突检查，并做两项窄化修复：

1. `【待核实】` 与 `【待人工核实】` 都属于明确的未核验声明，不应被误判成伪造来源；它们仍保持 `verified=false`。
2. 型号或软件版本只是适用范围。只有同一主题下的同一数值指标，或者紧跟“含义为、定义为、means”等释义标记的定义值，才能互相比较。不同部件、不同指标或不同知识点中的机型事实不得形成冲突。

数字比较需规范化中文数字、正负号、小数、范围端点、上下限和常见单位别名。定义差异只产生人工复核提醒，不自动隔离，避免同义改写被当成确定错误。

### 4. 来源证据随数据交付

仓库新增知识库来源台账与直接支撑本批资料的证据卡，不提交 `.firecrawl` 抓取缓存或受版权限制的原始手册副本。证据卡记录官方 URL、适用版本、定位、缓存 SHA 和使用边界。

已发现的三个证据卡缺口必须在同一变更中补齐：

- OSHA Robot System Safety 缓存哈希 `49e17c...04efb`；
- Universal Robots TCP Configuration 缓存哈希 `cd62c3...739b`；
- Universal Robots Robot Program Configuration 缓存哈希 `eb0b34...ae16`。

同一网页在不同抓取批次产生不同缓存文件时，证据卡同时保留旧哈希与本次采用哈希，不覆写历史记录。

## 验收标准

1. `data/kb/robotics.jsonl` 恰有 120 条、ID 为连续的 `KB-001` 至 `KB-120`，且无重复。
2. `KB-001` 至 `KB-026` 与导入前基线完全一致。
3. `KB-027` 至 `KB-120` 恰有 94 条，全部为 sourced、unverified、Demo 禁用。
4. 15 个知识点均有资料；每条新增记录的 REF、URL 与 SHA 均可在来源台账或证据卡中追踪。
5. 普通检索加载 120 条；`demo_only=True` 仍加载 20 条，Demo 来源清单验证通过。
6. 改进后的知识库审计不产生错误；历史跨来源近重复可保留为明确提醒，不影响入库。
7. 审计器的反例测试、来源契约测试、完整单元测试与 `git diff --check` 全部通过。

## 非目标

- 不把机器审核结果写成 `verified=true`。
- 不修改前端排版、模型路由、评分机制或当前 20 条 Demo 来源。
- 不导入候选工作区的 `KB-001` 至 `KB-026` 历史版本。
- 不提交抓取缓存、厂商 PDF 或其他可能受再分发限制的原始材料。
