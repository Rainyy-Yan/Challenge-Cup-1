# XH-202630 任务书驱动的产品落地设计

> 状态：实施基线  
> 日期：2026-09-03  
> 总负责人：肖云涵  
> 上位依据：官方《领域知识个性化生成与多智能体协同决策系统研究比赛方案》第 4-10 页

## 1. 目标与边界

本轮目标不是扩展模型或重做界面，而是把现有可运行研究原型收敛成能够按官方
任务书验收的产品候选：要求有明确映射，系统能够运行，指标能够由冻结数据复算，
证据能够追溯，后续材料可以只引用同一组结果。

官方要求与内部强化门槛分开管理：

- 官方硬要求包括一个垂直领域、至少三个职责明确的智能体、三种资源形态、动态
  反馈、三类可视化、源码与部署说明、单元测试、至少两组差异化初始数据，以及
  满分档的三类画像、五十组以上测试和三项指标门槛。
- 三百条知识切片、双人盲评、置信区间、证据索引状态机属于项目为提高可信度设置
  的内部门禁，不得写成官方原文要求。
- 本轮不新增生产鉴权、数据库、多租户、移动端、第二领域，也不继续做非阻塞视觉
  微调。

## 2. 当前基线与关键缺口

现有系统已经具备工业机器人领域、三份合成画像、八类智能体、分析-生成-校验-
决策时间线、讲义/SOP/测验、三类图表和反馈再生成。源码、部署入口、420 项 Python
测试、15 项前端测试和 50 组规则评测也已经存在。

阻止其成为正式交付的核心问题不是功能数量，而是证据层级：

1. `evalkit.run_eval` 的“幻觉率”只验证输出与项目知识库的一致性；知识库错误时，
   该指标仍可能为零。
2. 现有“适配准确率”由生成资源的同一规则反向检查，属于规则一致性，不是独立
   效果测量。
3. Demo 来源台账尚无完整人工签核，机器核对不能提升为 `human_verified`。
4. 现有人工评分工具只计算评分者一致性，没有生成三项官方指标、置信区间和保守
   达标结论。
5. 最终 PDF、PPT、视频、报名表和提交包必须等待可信指标冻结后再定稿。

## 3. 方案选择

### 方案 A：直接沿用规则评测结果

实现成本最低，但评测者和被评对象同源，不能证明专业正确性或真实适配效果，拒绝。

### 方案 B：人工给独立真值，程序生成统计证据（采用）

冻结系统输出后，由两名互不可见系统结论的评分者独立标注；分歧由第三人仲裁。
程序校验样本、计算一致性、三项指标、置信区间和门槛，只在证据充分时给出
`pass`。该方案与现有 `tools.rating` 可以衔接，且不伪造人工结论。

### 方案 C：只依赖外部大模型裁判

可降低人工成本，但裁判仍可能产生领域错误，且其独立性、版本和可重复性较弱，
只能作为辅助分析，不能作为最终真值。

## 4. 评测子系统架构

新增 `evalkit.formal_scorecard`，只消费冻结的人工真值 JSON，不调用生成模型，也不
修改知识库。输入、计算和输出分离：

```text
冻结的 50+ 用例与系统输出
        |
        v
两名独立盲评表 --分歧--> 第三人仲裁
        |
        v
formal_truth.json（样本级不可变事实）
        |
        v
结构校验 -> Kappa -> 三项指标 -> 聚类 Bootstrap 区间 -> 保守门禁
        |
        v
scorecard.json + scorecard.md
```

### 4.1 输入契约

真值文件包含：

- `dataset_id`、`frozen_at`、`system_commit`、`seed` 和不少于 50 个 `case_id`；
- 三类画像标识；
- 独立性声明，包括两名评分者、是否隐藏系统结论、是否独立完成；
- `claims`：断言、两名评分者标签、最终仲裁标签；
- `adaptations`：学习者、资源、两名评分者标签、最终仲裁标签；
- `coverage_universe`：预先冻结的核心知识点全集、权重、是否产出有效资源及证据 ID；
- 仲裁者身份和所有分歧条目的仲裁结果。

评分者身份使用项目内稳定代号；公开报告不写联系方式或其他个人敏感信息。

### 4.2 结构与独立性门禁

出现以下任一情况，报告状态为 `not_assessable`，不得给出达标结论：

- 唯一测试用例少于 50，或差异化画像少于 3；
- 系统提交不是 40 位 Git SHA，或数据集缺少冻结时间和固定种子；
- 评分者少于两人、评分者相同、看过系统结论或未独立评分；
- 两名评分者的共同有效标注不足，或 Cohen's Kappa 小于 0.60；
- 分歧没有第三人仲裁，或仲裁者与两名评分者重合；
- `无法判断` 比例导致可判定率低于 95%；
- 核心知识点全集存在未判定项、重复 ID、非正权重或缺少证据引用。

## 5. 数学口径

### 5.1 专业知识谬误率

对全部可判定断言，令最终仲裁标签为不支持时 `y_i=1`，支持时 `y_i=0`：

```text
H = (sum y_i) / n_claim
```

断言在同一测试用例内可能相关，因此不把所有断言错误地视作独立伯努利样本。
置信区间使用按 `case_id` 聚类的非参数 Bootstrap：每轮有放回抽取同样数量的测试
用例，带出该用例的全部断言，重算 `H`；固定随机种子，重复 10,000 次，取 2.5%
和 97.5% 分位数。只有 95% 区间上界严格小于 0.05 才判定该项达标。

### 5.2 画像-资源难度适配准确率

对全部可判定资源，令仲裁标签为合适时 `a_i=1`，偏易或偏难时 `a_i=0`：

```text
A = (sum a_i) / n_fit
```

同样按 `case_id` 聚类执行 10,000 次 Bootstrap。只有 95% 区间下界不小于 0.85
才判定达标。系统内部的难度值、掌握概率和原规则不进入评分者材料。

### 5.3 核心知识点覆盖率

覆盖全集在评测前冻结。对知识点 `k`，权重 `w_k>0`；只有产出至少一种包含有效
引用、正文非空且通过审核的资源时 `c_k=1`，否则为零：

```text
C = sum(w_k * c_k) / sum(w_k)
```

这是对完整冻结全集的普查，不做抽样置信区间。只有所有核心知识点均有明确判定且
`C >= 0.90` 才达标。

### 5.4 评分者一致性

分别对断言和适配任务计算 Cohen's Kappa：

```text
kappa = (p_o - p_e) / (1 - p_e)
```

`p_o` 为实际一致率，`p_e` 为按两名评分者边际分布计算的随机一致率。`kappa < 0.60`
时不能取平均或强行出分，必须对齐标准后重新盲评。

### 5.5 总结论

正式三指标结论不是简单多数判断：只有数据完整性门禁、独立性门禁、两项一致性
门禁、三项保守指标门禁全部通过时，`overall_status` 才为 `pass`。任何一项证据
不足都返回 `not_assessable`；指标计算完成但至少一项未过门槛时返回 `fail`。
该状态是项目证据门禁，不冒充评委对 100 分制的最终评分。

## 6. 用户故事与验收标准

### US-1 评测负责人冻结输入

作为评测负责人，肖云涵需要把候选提交 SHA、随机种子、50 组以上用例和系统输出
冻结，使任何人能够确认评分针对的是哪一版产品。

验收：真值文件通过结构校验；SHA、时间、种子、用例数和画像数进入报告；修改任一
冻结字段会改变文件哈希。

### US-2 领域评分者独立盲评

作为领域评分者，我只能看到学习者、资源或断言及必要来源，不能看到系统结论和
另一位评分者答案。

验收：评分材料不包含系统 verdict、难度分、共识等级或另一评分者标签；两份评分
结果可按稳定 `item_id` 对齐。

### US-3 仲裁者处理分歧

作为仲裁者，我需要查看两方分歧及原始证据，逐条给出最终标签，而不是让程序取
平均。

验收：每个分歧都有第三人标签；仲裁者不等于任一评分者；缺少任一仲裁时报告拒绝
出正式结论。

### US-4 评审者复算三项指标

作为评审者，我运行一条命令即可从冻结真值重建 JSON 和 Markdown 计分卡，并看到
分子、分母、点估计、区间、阈值、门禁和限制。

验收：相同输入、种子和 Bootstrap 次数得到字节稳定的核心统计；错误、缺失、低
一致性和边界阈值均有自动测试。

### US-5 交付负责人回填证据

作为交付负责人，我需要从 G0-G4 映射表定位每项任务书要求的实现、测试和最终
材料状态。

验收：每项官方要求至少有一个交付物路径、一个证据路径、责任角色和当前状态；
缺失项明确标记为阻塞，不能以计划文件代替完成证据。

## 8. 质量保障

- 单元测试：公式、分位数、Kappa、结构校验、状态机和边界条件。
- 集成测试：从真值 JSON 到 JSON/Markdown 报告的完整命令行流程。
- 回归测试：现有 Python、Node 前端、证据索引和评测工具全部保持通过。
- 用户验收：在干净目录按部署说明启动服务；以三类画像各跑一次；至少完成一次
  反馈再生成；从冻结真值复算计分卡。
- 安全检查：不提交 `.env`、密钥、联系方式、真实学习者隐私或受限资料正文。
- 差异检查：每个提交只包含计划内文件；阈值若变化必须单独提交且先于评测数据。

## 9. 决策记录

- ADR-001：官方原文件为上位规范，仓库内部基线只用于补充验收细节。
- ADR-002：模型负责生成语言，数学、状态机、审计门禁和最终计分由确定性代码负责。
- ADR-003：正式指标只接受独立人工真值；自动规则结果保留为内部一致性和回归证据。
- ADR-004：置信区间按测试用例聚类 Bootstrap，避免把同一会话中的多条断言错误地
  当作彼此独立。
- ADR-005：正式达标采用保守区间边界；样本不足返回不可评估，不用点估计冒险过线。
- ADR-006：不自动填写复核人、仲裁人、授权结论或报名表，不用程序伪造人工事实。
