## 一、交付成功定义

最终成果不是“代码能跑”或“指标脚本输出达标”，而是评委可以独立完成以下验证：

1. 按部署说明在普通评审电脑上启动系统，并通过唯一在线入口访问 Demo。
2. 输入差异化学习者画像，看到学情诊断、协同调度、三类个性化资源和可视化报告。
3. 完成一次学习交互反馈，看到系统触发降维解释、巩固或进阶挑战并重新生成资源。
4. 展开任一知识断言，看到知识库切片、来源定位、核实状态和审核结果。
5. 从原始测试数据重新运行评测，得到可复现的指标、消融和红队结果。
6. 在 PDF、PPT、视频、Demo 和评测报告中看到一致的版本、数字和能力边界。

交付同时满足“可运行、可理解、可复现、可举证、可提交”五项条件，才算完成。

| 评分维度 | 官方权重 | 最终必须呈现的结果 | 核心证据 |
|---|---:|---|---|
| 作品完整性 | 30 | 学情画像 → 诊断 → 多智能体生成/审核 → 三类资源 → 反馈 → 动态决策更新的完整闭环 | 可操作 Demo、调度时间线、状态机测试、完整演示视频 |

| 用户体验 | 15 | 评委无需阅读源码即可理解“谁在做什么、为什么这样决策、生成了什么” | 统一视觉 Demo、完整资源正文、三类图表、清晰反馈结果 |

## 三、最终提交包结构

最终压缩包按赛事要求命名：`<学校>—<申报人>—<作品名称>—<手机号>.zip`。包内使用以下稳定结构：

```text
作品提交包/
├── 00_提交说明与文件清单.pdf
├── 01_作品设计实现方案.pdf
├── 02_作品介绍与答辩PPT.pptx
├── 03_系统演示视频.mp4
├── 04_源代码/
│   └── agentedu/
├── 05_部署说明.md
├── 06_测试数据与评测报告/
│   ├── 学习者画像/
│   ├── 知识库与来源清单/
│   ├── 50组以上测试明细/
│   ├── 三项指标报告/
│   ├── 消融与红队报告/
│   └── 人工评分与一致性报告/
├── 07_开源仓库与知识产权说明.md
├── 08_经报名系统审核的报名表.pdf
└── CHECKSUMS.sha256
```

提交包不得包含缓存、密钥、虚拟环境、临时日志、重复 PDF、过期快照或无法说明来源的数据。源代码目录必须保留 README、测试、知识库、样例画像和一键运行入口。

### 3.1 提交渠道与报名表一致性

- 2026 年 9 月 5 日前，将完整压缩包提交至发榜单位指定邮箱 `602808600@qq.com`。
- 经报名系统审核通过的报名表必须随作品统一打包，且学校、申报人、作品名称、团队成员等信息与系统填报内容完全一致。
- 如压缩包过大无法通过邮件附件发送，上传至相对安全的云盘，并在邮件中提供链接、提取码及包含上传时间的云盘文件截图。
- 若源代码使用私有仓库交付，必须在提交前向评审开放访问权限，并在 `07_开源仓库与知识产权说明.md` 中写明访问方式；公开仓库则提供固定提交或版本标签，避免评审期间内容漂移。

## 四、Demo 验收要求

### 4.1 唯一运行入口

- 在线/本地服务入口：运行 `py -3 server.py` 或 `python3 server.py`，浏览器打开 `http://127.0.0.1:8000`。

该入口必须无 JavaScript 异常、空白区域、资源计数错误或流程中断。

### 4.2 必须可见的完整流程

1. 至少 3 组差异化合成画像可直接选择，并明确标注为合成数据。
2. 支持自由自述、背景抽取、补充追问和自适应测评。
3. 显示知识盲区、掌握概率、证据强度和建议起始难度。
4. 显示诊断、规划、双专家生成、辩论/交叉验证、审核、组装和就绪状态。
5. 对每个学习知识点展示讲义、实操指南、分阶测试题三种完整资源，而非只有资源标题或断言列表。
6. 资源正文同时显示知识来源、证据分、共识等级和核实状态。
7. 学习反馈必须使用真实题目与选项；提交后显示正确率、决策阈值、动作原因和新增资源。
8. 显示知识盲区图、资源难度匹配图、学习路径图；增强版同时展示能力雷达和证据区间。

### 4.3 演示模式边界

- 默认参赛演示使用无故障注入的数据，不把注入结果当正式跑分。
- 幻觉注入和数值漂移保留为独立“机制验证模式”，必须有清晰开关、说明和结果口径。
- 页面明确显示当前为真模型、规则桩或降级模式。
- 真模型失败、额度耗尽或网络中断时自动降级，但必须给出可见提示，不能静默改变演示版本。

## 五、数据与评测证据

### 5.1 知识库

- 至少覆盖工业机器人一个真实垂直领域及明确岗位场景。
- 所有进入最终 Demo 的切片必须有真实来源、页码/章节/条款等定位和人工核实记录。
- 每个重点演示知识点至少准备 3 条可区分的有效上下文，使宽窄检索和交叉验证具有真实意义。
- 官方未规定切片总量；内部冲奖目标为 `300+` 条。若时间不足，优先保证演示链路所用切片 100% 可回溯，而不是堆积未核实数量。
- 机器摄入只能写入 `sourced` 或未核实状态，不能自动写入 `verified`。

### 5.2 学习者与测试集

- 最少 3 组不同学历、理论基础和实操经验的合成画像。
- 每组保留输入画像、前测作答、协同中间数据、生成资源和反馈后结果。
- 批量评测不少于 50 组，固定随机种子并保留运行配置、时间戳和原始明细。

### 5.3 指标真值与报告口径

- 幻觉率以人工核实知识库或独立领域专家判断为真值，不能只证明“与知识库一致”。
- 难度适配准确率由独立评分者或独立标注集判断，不能用生成难度的同一规则自我验证。
- 核心知识点覆盖率必须预先固定知识点全集和覆盖判据。
- 至少两名独立评分者盲评，并报告一致性；一致性不足时先统一标准后重标，不直接取平均。
- 每项指标同时给出分子、分母、样本量、置信区间或限制说明。

### 5.4 必须保留的工程证据

- 完整单元测试通过，数量不低于当前 265 项基线。
- Python 与浏览器规则一致性测试通过。
- 审核开启/关闭和辩论开启/关闭的消融结果可复现。
- 红队按 H1-H6 分类报告检出率和误伤率；H5、H6 若仍不足，必须如实列为短板。
- 题库报告包含答案位置、结构瑕疵、待改题目以及真实作答后的难度和区分度。

## 六、文档、PPT 与视频

### 6.1 技术方案 PDF

只保留一个权威版本，至少包含：封面、目录、问题定义、用户场景、总体架构、智能体职责、数据流、关键算法、创新机制、知识溯源、评测设计、结果、消融、局限、部署、合规和团队分工。

PDF 中的指标必须与最终评测报告一致。页数、版本日期、系统名称、角色数量和知识库规模不得与 README、PPT、视频冲突。

### 6.2 答辩 PPT

建议控制在 12-16 页，围绕一条证据链组织：

1. 行业痛点与榜题目标；
2. 差异化学习者场景；
3. 多智能体架构与协同闭环；
4. 辩论、审核和知识溯源创新；
5. Demo 完整流程；
6. 三类个性化资源与反馈迭代；
7. 评测、消融和红队证据；
8. 当前边界、迁移价值与总结。

PPT 不堆代码截图；每个核心结论配一张图、一个案例或一项数据证据。

### 6.3 十分钟以内演示视频

建议时长 9 分钟左右并预留平台转码余量：

| 时间 | 内容 |
|---|---|
| 0:00-0:40 | 问题、目标和系统定位 |
| 0:40-1:30 | 架构与智能体职责 |
| 1:30-3:00 | 输入画像、自述访谈和学情诊断 |
| 3:00-5:00 | 协同时间线、辩论、审核与溯源 |
| 5:00-6:30 | 三类完整学习资源和可视化报告 |
| 6:30-7:40 | 作答反馈、降维或进阶迭代 |
| 7:40-8:40 | 指标、消融、红队和人工真值 |
| 8:40-9:10 | 局限、迁移价值和结束页 |

视频必须录到真实点击、真实页面状态和完整资源，不用纯动画代替系统运行。画面中不得出现 API Key、个人联系电话、调试控制台或无关窗口。

## 七、模型运行与合规边界

- 至少录制一条真模型完整流程，运行前通过模型体检；模型不可用时应由自动降级链路给出明确状态。
- API Key 只通过环境变量配置，不写入源码、HTML、日志或视频。
- 学习者画像使用合成数据并在材料中明确说明；真实数据必须脱敏并说明授权范围。
- 知识库以自行整理的技术要点为主，保留来源定位；教材、企业手册和内部资料不得大段复制，受限资料必须取得授权。
- 不将内存会话、无鉴权本地服务描述为生产系统；对外定位为可运行研究原型和比赛 Demo。

## 八、交付门禁与禁止提交条件

### 8.1 五道交付门禁

| 门禁 | 通过条件 |
|---|---|
| G0 要求覆盖 | 官方要求逐条映射到交付物和证据，无遗漏 |
| G1 Demo 可用 | 在线入口完成完整闭环，浏览器控制台无错误 |
| G2 证据可信 | 测试、评测、消融、红队和人工真值齐全，数字可复现 |
| G3 材料一致 | PDF、PPT、视频、README、Demo 使用同一版本和同一口径 |
| G4 封包可交 | 在一台干净电脑解压复测，通过清单、哈希、命名和视频时长检查 |

### 8.2 任一出现即禁止提交

- `server.py` 无法启动、在线流程停在 0 步或出现 JavaScript 异常。
- 三类资源只有名称，没有可阅读正文、操作步骤或测试题。
- 默认 Demo 使用故障注入数据，却没有明显标注或仍把结果当正式指标。
- 知识库引用无法定位，或把未核实内容写成已核实。
- 把“规则一致性 100%”表述成“真实适配准确率 100%”。
- 技术 PDF 存在两个内容不同的版本，或 README 页数与实际文件不一致。
- 压缩包缺少 PPT、十分钟内视频、部署说明、测试数据或报名表。
- 源码、日志或录屏中出现密钥、个人敏感数据或未经授权资料。
- 最终压缩包未在独立目录或干净电脑上完整复测。

## 十、当前基线与收口边界

截至 2026 年 9 月 1 日，当前基线如下：

- 简单版服务 Demo 可完成诊断、15 步生成和反馈后的 21 步动态闭环。
- 离线打包版已移除，G1 只验收唯一在线入口。
- 265 项单元测试通过；50 组批量评测的三项规则指标名义达标。
- 知识库 26 条，仅 5 条标记核实，完整可回溯出处为 0；正式效果指标尚无独立真值。
- 红队 H5 过度泛化、H6 似真外推检出率均为 67%。
- 47 道题中 19 道待改，尚无真实作答数据完成难度与区分度标定。
- 当前在线入口使用独立配置的 MiniMax-M3 与 deepseek-v4-pro，并保留自动降级。
- 技术说明存在两个内容不同的 PDF，当前压缩包未包含 PPT 和演示视频。

本次首次提交不扩展生产级鉴权、数据库持久化、多租户、移动端或完整第二领域。这些内容可以作为终审升级方向，但不得挤占 G0-G4 的交付时间。
