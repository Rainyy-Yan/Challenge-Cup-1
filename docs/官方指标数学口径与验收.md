# 官方指标数学口径与验收

> 适用范围：本文件规定仓库中 `evalkit.formal_scorecard` 的可复算证据门禁。
> 它服务于开发、验收和评审，不替代赛事评委的 100 分制评分。官方任务书第 8 页将“测试用例不足 50 组”列为测试方案不完整的扣分条件，故本项目以 `>=50` 作为完整性边界；这不是任务书单列的满分档原文。双人盲评、10,000 次 case-cluster Bootstrap、保守置信区间与证据状态机均为内部可信度加强。

## 读者与使用方式

- **开发者**：以本文和 `evalkit/formal_scorecard.py` 共同维护输入契约、统计实现与测试；程序只处理冻结 JSON，不读取 `.env`，不调用模型提供方，也不生成任何人工身份、标签或授权结论。
- **验收负责人**：先冻结候选提交、用例、画像、输出和覆盖全集，再组织两名独立盲评与第三人仲裁；最后运行命令、保存输出和哈希。
- **评审者**：从冻结真值文件运行同一条命令，检查 JSON、Markdown、门禁错误和限制。`pass` 仅表示该证据门禁通过，不表示赛事最终得分或外部材料已经完成。

官方任务书的逐项路径、当前状态和外部缺口见[官方任务书落地矩阵](官方任务书落地矩阵.md)。其中 `>=50` 用例对应上述第 8 页的完整性扣分边界；双人盲评、置信区间和 G0–G4 索引是本项目的内部可信度加强措施，不要将它们表述为官方原文条款。

## 可运行入口与产物

从仓库根目录运行：

```powershell
py -3 -X utf8 -m evalkit.formal_scorecard --truth <formal_truth.json> --out <report-directory>
```

对于可读取的 JSON，命令总会在 `<report-directory>` 写入 `scorecard.json` 与 `scorecard.md`。当 `overall_status` 为 `pass` 或 `fail` 时退出码为 `0`；真值文件无效、不完整或无法评估时写出 `not_assessable` 报告并以退出码 `2` 结束。文件读取或 JSON 解析失败也会写出包含错误信息的 `not_assessable` 报告并退出 `2`。

空模板 `data/evaluation/formal_truth.template.json` 故意是 `draft`，没有评分者、用例或结论。因此下面的命令预期退出 `2`，但仍生成两份报告；它证明错误路径可审计，**不证明任何官方指标达标**。

```powershell
py -3 -X utf8 -m evalkit.formal_scorecard --truth data/evaluation/formal_truth.template.json --out delivery/evidence/local-template-check
```

## 冻结真值契约和信任边界

`validate_truth(data)` 在计算前执行失败关闭校验。它要求：

- 根级 `version` 与 `artifact_manifest.version` 都必须是**真正的整数** `1`（布尔值 `true` 拒绝）；`status` 为 `frozen`；`frozen_at` 是带时区的 ISO-8601 时间；`seed` 是非负整数；只使用 `provenance.repository_sha`（40 位小写十六进制 Git SHA）和 `provenance.artifact_manifest_sha256`（64 位小写 SHA-256），根级不设提交字段。
- `blind_to_system_output` 与 `independent_ratings` 都为 `true`；`dataset.dataset_id` 是稳定、非空、去首尾空格的字符串。
- `dataset.cases` 至少有 50 个大小写无关的唯一 `case_id`；`dataset.profile_ids` 至少有 3 个大小写无关的唯一、去首尾空格的 ID。每个 case 必须引用声明的画像。
- `reviewers` 恰好包含两名不同的稳定身份；`review_protocol.human_reviewer_roster` 是名单，名单中每人都有非空 ID 且 `attested_human: true`，两名评分者必须在名单中。该声明只校验输入字段，不能证明现实世界身份；签名、任务分配与利益冲突记录仍是仓库外人工证据。
- `claims` 的标签只能是 `yes`、`no`、`unassessable`；`adaptations` 的标签只能是 `correct`、`incorrect`、`unassessable`。每条记录必须有唯一 ID、已知 `case_id`、两名评分者的完整标签和有效最终标签；不得携带 `system_conclusion`、`machine_conclusion`、`model_conclusion`、`system_label`、`machine_label` 或 `model_label` 字段。
- 两人标签相同时，`final_label` 必须等于共同标签。不同则必须由名单中的第三人用 `adjudicated_by` 仲裁，且仲裁者不能是任一评分者。程序不会投票、平均或代写仲裁结果。
- 数据集整体必须有 `>=50` case 与 `>=3` profile；claims 和 adaptations 各自覆盖的 case 还必须代表 `>=3` 个 profile，且最终标签可判定占比必须 `>=0.95`。每类还必须各有 `>=50` 个不同 case 的共同有效双评 pair，且共同有效 pair 占该类全部行的比例 `>=0.95`；Kappa 只使用这些 pair。
- `coverage_universe` 是评测前冻结的全集。每个知识点 ID 唯一、权重为有限正数、`covered` 为布尔值；`covered: true` 必须给出至少一个非空 `evidence_ids`，且总权重必须为正。

`artifact_manifest` 是版本 1 的严格闭集：`artifacts` 和 `citations` 都是字段白名单记录；artifact 的 `content` 与 citation 的 `excerpt` 分别按严格 UTF-8 原文计算 SHA-256，manifest 本身按 `sort_keys=True`、紧凑分隔符、`ensure_ascii=False` 的 canonical JSON 计算哈希并写入 `provenance.artifact_manifest_sha256`。五类 artifact 为 `profile_snapshot`、`case_input`、`claim_output`、`resource_output`、`coverage_evidence`。`dataset.profile_artifact_ids`、case、claim/resource 行与 coverage point 必须同 manifest 做双向 ownership 和每类 ID 闭集核验：profile 的 `subject_id` 是 profile ID，case input 的 `subject_id` 是 case ID，claim/resource 的 `subject_id` 是行 ID 且 `case_id` 匹配，coverage evidence 的 `subject_id` 是知识点 ID。profile 内容哈希必须唯一；至少 50 个唯一 `(profile snapshot sha256, case input sha256)` 组合；claim/resource 正文允许在不同合法 owner 间重复。每个 coverage evidence 必须引用已批准 citation；`covered=true` 必须有非空 evidence，`covered=false` 必须严格为 `evidence_ids=[]`。这些内部绑定只证明内容/引用关系，不证明外部来源、摘录、签名或身份真实性。

任何以上错误、两类任务任一 Kappa 未定义或低于 `config.FORMAL_KAPPA_MIN`（当前 `0.60`），都会令报告进入 `not_assessable`。报告仍列出每个可诊断错误与占位指标，供负责人修复输入；不得将该报告改写为通过结论。

## 统计口径

### 共同记法、样本与区间

只使用最终仲裁标签不是 `unassessable` 的记录计算三项点估计。断言和适配记录按 `case_id` 聚类：每次 Bootstrap 以固定 `seed` 对全部 case 簇有放回抽取同样数量的簇，带出簇中的全部记录；`cluster_bootstrap_interval(..., samples=10000)` 将 10,000 次重算结果排序，按线性插值取 2.5% 和 97.5% 分位数。

对二项比例，`wilson_interval(successes, total, confidence=0.95)` 采用双侧 Wilson score 区间：令 `p=x/n`、`z=Phi^{-1}(0.975)`，则

```text
center = (p + z^2/(2n)) / (1 + z^2/n)
margin = z * sqrt(p(1-p)/n + z^2/(4n^2)) / (1 + z^2/n)
Wilson = [max(0, center-margin), min(1, center+margin)]
```

实现先拒绝非法计数；当 `n=0` 时立即返回 Wilson 区间 `[0, 0]`，因此即使 `confidence` 非法也不会继续校验。只有 `n>0` 时，非法置信度才会抛出错误。正式二项指标不从两个区间中挑有利的一侧，而使用**保守包络**：

```text
interval = [min(Wilson_low, Bootstrap_low), max(Wilson_high, Bootstrap_high)]
```

### 专业知识谬误率（`hallucination_rate`）

令每个可判定断言的最终标签为 `yes` 时 `y_i=1`，为 `no` 时 `y_i=0`：

```text
H = sum(y_i) / n_claim
```

报告字段 `numerator` 是 `yes` 数，`denominator` 是可判定断言数，`point_estimate` 是 `H`。门槛唯一来源是 `config.TARGET_HALLUCINATION`（当前为 `0.05`），评分器只引用该配置；只有保守包络的**上界严格小于**该值时 `conservative_decision` 才是 `true`。等于阈值也失败。

### 画像—资源难度适配准确率（`adaptation_accuracy`）

令每个可判定资源适配记录的最终标签为 `correct` 时 `a_i=1`，为 `incorrect` 时 `a_i=0`：

```text
A = sum(a_i) / n_fit
```

报告字段 `numerator` 是 `correct` 数，`denominator` 是可判定适配记录数，`point_estimate` 是 `A`。门槛唯一来源是 `config.TARGET_ADAPT`（当前为 `0.85`），评分器只引用该配置；只有保守包络的**下界大于或等于**该值才通过。评分材料不能暴露系统结论、内部难度、掌握概率或原规则；系统规则一致性不能替代这一独立人工适配判断。

### 核心知识点加权覆盖率（`coverage`）

令冻结全集中知识点 `k` 的正权重为 `w_k`，其 `covered` 布尔值为 `c_k`（真为 1，假为 0）：

```text
C = sum(w_k * c_k) / sum(w_k)
```

报告的 `numerator` 是已覆盖权重，`denominator` 是总权重，`point_estimate` 是 `C`。这是完整冻结全集的加权普查，`interval` 固定为 `null`，不计算 Wilson 或 Bootstrap 区间。门槛唯一来源是 `config.TARGET_COVERAGE`（当前为 `0.90`），评分器只引用该配置；`C >=` 该值才通过。任何已覆盖点都必须有证据 ID，未覆盖点必须为空列表。

### Cohen's Kappa（`kappa`）

断言与适配分别从两名评分者的原始标签计算 Cohen's Kappa，且如果任一评分者把某条标为 `unassessable`，该对标签不进入 Kappa：

```text
kappa = (p_o - p_e) / (1 - p_e)
```

`p_o` 是实际一致率，`p_e` 是两名评分者按各自边际分布得到的随机一致率。没有可用成对标签，或 `p_e = 1` 导致分母为零时 Kappa 未定义。两类任务都要求 `>= config.FORMAL_KAPPA_MIN`（当前为 `0.60`）；不满足时重新对齐标准并盲评，不能用平均值绕过。Markdown 同时列出每项 Kappa 的 `n`、`agreement` 与 `value`，并列出最终 `assessable_share` 与 `common_pair_cases/common_pair_share`；二项指标列出 Wilson、Bootstrap 和保守包络。

## 状态机、门槛与输出解释

| 条件 | `overall_status` | CLI 退出码 | 可对外表述的范围 |
|---|---|---:|---|
| 真值校验、独立性、覆盖或 Kappa 门禁任一失败 | `not_assessable` | 2 | 仅能说明输入或人工证据不足及错误；不得宣称指标达标。 |
| 全部输入门禁通过，但三项保守决策中至少一项失败 | `fail` | 0 | 可报告冻结数据下的失败结果和限制；不得改写为达标。 |
| 输入门禁通过，谬误率上界 `< config.TARGET_HALLUCINATION`、适配率下界 `>= config.TARGET_ADAPT`、覆盖率 `>= config.TARGET_COVERAGE`，且两项 Kappa 均 `>= config.FORMAL_KAPPA_MIN` | `pass` | 0 | 仅表示该冻结数据的正式指标证据门禁通过。 |

`data_quality.gates` 始终显示以下实际值、阈值、`>=` 比较与布尔决定：cases `50`、profiles `3`、claims/adaptations assessable share `0.95`、每类 common-pair cases `50`、每类 common-pair share `0.95`，以及两类 Kappa `config.FORMAL_KAPPA_MIN`。评审应同时查阅 `provenance`、每项分子/分母、点估计、Wilson/Bootstrap/包络区间、Kappa n/agreement/value、可判定与共同 pair 字段、阈值、保守决定和 `limitations`。

### 说明性示例，非赛事结果

假设冻结文件有 100 条可判定断言，其中 2 条最终标签为 `yes`，则点估计为 `H=2/100=0.02`。按 `wilson_interval(2, 100)`，Wilson 上界约为 `0.070012`；即使本例 case-cluster Bootstrap 上界更低，保守包络仍取两者较高的 `0.070012`，故不满足严格的 `<0.05`。这是为解释“点估计不足以过线”而设的**说明性示例，非赛事结果**，不能登记为任何 G2 正式 scorecard。

## 验收步骤与错误处置

1. 负责人冻结候选 SHA、数据集 ID、画像、case、系统输出、覆盖全集和种子；保留不可变副本与哈希。
2. 两名独立人工评分者在不看系统结论和对方标签的条件下完成标注；第三位不同的人工仲裁者逐项处理分歧。系统或开发者不得替代上述角色。
3. 运行 CLI；检查退出码，并保留命令、输入哈希、`scorecard.json`、`scorecard.md`、评分分配记录、签名/授权记录与仲裁日志。
4. 若退出 `2`，按报告 `data_quality.errors` 修复真值或补足人工证据，使用新的冻结版本重新评分。不要就地覆盖原冻结文件。
5. 若结果为 `fail`，保留失败报告、定位改进项，修改系统后以新提交和新冻结数据完整重走盲评；不得只重算有利子集。
6. 只有实际形成、经规定人工签字批准的结果才可把 G2 正式 scorecard 从计划记录提升为候选/批准状态，并绑定对应提交 SHA。
