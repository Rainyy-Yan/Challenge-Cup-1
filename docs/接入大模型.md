# 接入大模型

## 一、三步接上

```bash
export AGENTEDU_API_KEY=sk-xxx
export AGENTEDU_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
export AGENTEDU_MODEL=qwen3.7-plus

python3 -m evalkit.doctor        # 第一件事，先体检
```

在 Windows PowerShell 中使用同一组变量（密钥只保留在当前终端，不写入仓库）：

```powershell
$env:AGENTEDU_API_KEY = '<你的密钥>'
$env:AGENTEDU_BASE_URL = '<OpenAI 兼容端点>'
$env:AGENTEDU_MODEL = '<模型名>'
py -3 -m evalkit.doctor
py -3 cli.py P-A
```

只有 `doctor` 明确显示已连接真实模型后，第二条命令才算一次真模型流程；若没有密钥、端点或模型名，系统会继续走离线桩，不能把那次运行称为真模型结果。

### 本项目的 DeepSeek 配置

本次 Demo 选用 DeepSeek。请在**启动服务的同一个 PowerShell 窗口**中设置以下变量；密钥不要写入代码、文档或 Git：

```powershell
$env:AGENTEDU_API_KEY = '<在 DeepSeek 平台创建的 API Key>'
$env:AGENTEDU_BASE_URL = 'https://api.deepseek.com'
$env:AGENTEDU_MODEL = 'deepseek-v4-flash'
$env:AGENTEDU_MODEL_STRONG = 'deepseek-v4-pro'
$env:AGENTEDU_MODEL_MID = 'deepseek-v4-flash'
$env:AGENTEDU_MODEL_LIGHT = 'deepseek-v4-flash'
$env:AGENTEDU_RPM = '10'
$env:AGENTEDU_BUDGET_CALLS = '200'

py -3 -m evalkit.doctor
py -3 cli.py P-A
py -3 server.py
```

DeepSeek 官方文档列出的 OpenAI 兼容端点为 `https://api.deepseek.com`，当前模型名为 `deepseek-v4-flash` 与 `deepseek-v4-pro`；旧的 `deepseek-chat` 和 `deepseek-reasoner` 已进入弃用安排。`flash` 用于高频、低成本任务，`pro` 保留给本项目中答案正确性要求最高的命题任务。

**没配 key 系统照样跑**，自动退回离线桩，只是自述解析、命题、综合诊断走规则版。
所以接模型不是必需项，是增强项 —— 演示现场断网也不会挂。

体检脚本会逐项探明端点支持什么。不通过就别急着跑全流程：接模型最常见的三类
故障（JSON 模式不支持、模型名写错、限流），在全流程里表现出来**都是"生成结果
为空"**，极难定位。

## 二、选哪个模型

只要是 **OpenAI 兼容接口**都能接，改 `AGENTEDU_BASE_URL` 即可。
国内几家主流都提供兼容端点。

**选型的关键不是挑一个最好的，是按任务分档。** 这套系统里三类调用要求完全不同：

| 任务 | 档位 | 要求 | 出错代价 |
|---|---|---|---|
| 命题 `make_item` | strong | 严格遵循约束、不能瞎编 | **最高**，答案标错会污染学情模型 |
| 断言起草 / 核验 | mid | 中等，且有审核闸兜底 | 中，能被拦住 |
| 自述解析 / 综合诊断 / 简化 | light | 弱模型足够 | 低，且调用量最大 |

```bash
export AGENTEDU_MODEL_STRONG=<强模型>    # 只用于命题
export AGENTEDU_MODEL_MID=<中档模型>
export AGENTEDU_MODEL_LIGHT=<便宜模型>   # 调用量最大的那批
```

缺哪档就回落到 `AGENTEDU_MODEL`。全用旗舰是白烧钱；全用最便宜的，
命题闸门会天天拒收，通过率上不去。

### 选型建议

**先用免费额度把两三家都跑一遍 `doctor`，再决定。** 各家新用户通常都给
一批免费 token，够把全流程跑通很多遍。判断依据只看一个数：
**命题实测的通过率**（doctor 第 5 项）。这个数直接反映模型能不能按约束干活，
比任何榜单都贴合本项目。

优先考虑国产模型，除了成本，还有一条现实理由：**提交材料里要写数据合规**，
用境内服务省掉一堆解释。

> 价格和模型名变动很快（2026 年 8 月初还有厂商宣布要涨价），
> 这份文档不写具体单价，请以官方价格页为准。配好之后用
> `AGENTEDU_PRICE_IN` / `AGENTEDU_PRICE_OUT`（元/百万 token）
> 填进去，系统会自己算成本。

## 三、只用免费额度跑演示

比赛演示完全不需要花钱。三条路，按推荐顺序：

### 路线 A：厂商的永久免费档（最省事）

国内有厂商提供长期免费的小尺寸模型（通常是 Flash / Lite 这一档），
注册实名后即可用，接口同样是 OpenAI 兼容。

```bash
export AGENTEDU_API_KEY=<你的 key>
export AGENTEDU_BASE_URL=<该平台的 OpenAI 兼容端点>
export AGENTEDU_MODEL=<免费档模型名>
export AGENTEDU_RPM=10              # 免费档基本都限 RPM，按官方文档填
export AGENTEDU_BUDGET_CALLS=300    # 保护额度，见下

python3 -m evalkit.doctor
```

> **不要照抄网上的型号名。** 免费档的模型 ID 变动很频繁，有的旧 ID 已经下线
> 或被自动路由到新版本。以官方文档和控制台的模型列表为准，填错的表现是
> "生成结果为空"，很难定位 —— 所以务必先跑 `doctor`，它第 2 项就是探模型名。

### 路线 B：新用户赠送额度（够跑很多遍）

多数平台给新用户一批赠送 token，有效期几十天。对本项目来说绰绰有余：
一次完整测评加资源生成大约几十次调用。用它把 `doctor` 和全流程跑通，
再决定要不要付费。

### 路线 C：本地部署（彻底免费，且断网可用）

用 Ollama 之类的工具在本机跑一个小模型，它自带 OpenAI 兼容端点：

```bash
export AGENTEDU_API_KEY=ollama            # 本地不校验，随便填
export AGENTEDU_BASE_URL=http://localhost:11434/v1
export AGENTEDU_MODEL=<你拉下来的模型名>
export AGENTEDU_RPM=0                     # 本地不用限速
```

适合答辩现场：不依赖网络、不担心额度、数据不出本机（数据合规那条更好写）。
代价是小尺寸模型的命题通过率会低一些，`doctor` 第 5 项能直接看出来。

### 免费档的三条保护（代码里已经做了）

免费档真正的约束不是"能不能用"，是**每分钟请求数**和**总额度**。
没有这三条，一次演示很容易把额度打光，而且失败方式很难看。

| 开关 | 作用 | 为什么需要 |
|---|---|---|
| `AGENTEDU_RPM` | 主动限速 | 免费档限 RPM，超了返 429。靠重试硬扛的话，一次测评几十次调用大部分时间耗在退避等待上，现场看着像卡死。主动限速比被动挨罚好。 |
| `AGENTEDU_BUDGET_CALLS` | 调用次数硬上限 | 额度悄悄耗尽后，系统会一路回退规则版 —— **"能跑但已降级"是最坏的一种故障**。设了上限就在到顶前主动停用，并在 `stats()` 里标出 `budget_hit`。 |
| `AGENTEDU_CACHE` | 相同请求复用 | 系统提示词固定不变，评测批次里同一知识点会被反复起草，命中率可观。默认开启。 |

**额度用完不会崩。** 命题环节会捕获模型故障、返回 None、回退固定题库；
自述解析回退正则规则；综合诊断回退规则拼句。整条链路照样跑完，
只是那几处降级。演示现场额度用完还能继续演，和当场白屏，是两回事 ——
这条有测试盯着（`test_item_generation_degrades_instead_of_crashing`）。

### 免费档跑演示的建议配置

```bash
export AGENTEDU_MODEL_LIGHT=<免费小模型>   # 自述解析/综合诊断，量最大
export AGENTEDU_MODEL_STRONG=<免费小模型>  # 命题也用它，通过率低就少出题
export AGENTEDU_RPM=10
export AGENTEDU_BUDGET_CALLS=200
```

命题通过率低不影响演示完整性 —— 系统会回退到 47 道固定题库，
自适应测评、辩论、审核、资源生成全部照常。**免费档拿不下的只有"现场出变种题"
这一个增强点**，其余全都在。

## 三、省钱的几个点

- **批量调用**：多数平台的 batch 接口是实时价的五折，跑评测批次时用得上。
- **上下文缓存**：系统提示词固定不变，命中缓存后输入侧便宜一个数量级。
  本项目的提示词天然固定，收益明显。
- **错峰**：有的平台高峰时段加价，跑批量评测挪到夜里。
- **别拿旗舰模型写叙述**：`synthesize` 和 `diagnose_narrative` 加起来
  占调用量的大头，但对模型能力要求最低。

## 四、客户端已经处理掉的坑

`core/llm.py` 里的 `RealLLM` 不是最小实现，它处理了四件接真模型一定会遇到的事：

**重试。** 429 限流和 5xx 是常态不是异常。一次测评几十次调用，
没有指数退避的话中途断掉整条链路就废了。401/403 不重试 —— 重试多少次都没用，
快速失败比慢慢磨好。

**JSON 模式降级。** `response_format: {"type":"json_object"}` 是 OpenAI 的约定，
兼容接口不一定支持，不支持时直接报 400。客户端会自动降级：去掉该字段，
改在提示词里要求只输出 JSON，重试一次。**降级过一次就记住**，
后续不再白试，省掉一半的无效请求。

**按任务路由模型。** 见上表。

**用量与成本统计。** 不统计就不知道一次演示花多少钱，报告里也没法写成本。
`llm.stats()` 给出分任务的 token 数和折算金额。

这四条都有测试盯着（`tests/test_llm_client.py`，用本地假端点，不联网）。

## 五、接上之后哪些地方会变

| 环节 | 离线（无 key） | 接模型后 |
|---|---|---|
| 自述解析 | 正则规则抽取 | 模型抽取 + 规则校验兜底 |
| 命题 | 不可用，只用固定题库 | 现场出变种题，过四关审核 |
| 断言起草 | 按句切分知识库原文 | 生成式改写，仍需过审 |
| 综合诊断 | 规则拼句 | 模型归纳，数字仍由规则算 |
| 审核 / 辩论 / BKT / 选题 | **完全一致** | **完全一致** |

最后一行是重点：**判断逻辑不因为接了模型而改变**。模型负责产出内容，
规则负责把关和计算。这条边界是整个方案可信度的来源，接模型时不要越界。

`showcase.html` 双击打开时永远是离线模式（浏览器里没有 key，也不该有），
演示时要说清楚这个区别。

## 六、接上后必须重跑

```bash
python3 -m evalkit.redteam                       # 幻觉分类检出率
AGENTEDU_INJECT=0 python3 -m evalkit.run_eval --n 50
python3 -m evalkit.itemreport                    # 题目质量
```

现有的跑分都是离线桩产出的。真模型的幻觉形态比桩里注入的四类丰富得多，
审核规则大概率还要再补。README 里"共识分层相差 34 倍"那个结论
**必须用真模型重测**，不要直接拿去答辩。
