# 接入大模型

## 一、三步接上

```bash
# Windows PowerShell
Copy-Item .env.example .env

# macOS / Linux
cp .env.example .env

# 编辑仓库根目录 .env，只填写 AGENTEDU_API_KEY；两个模型已经固定

python3 -m evalkit.doctor        # 第一件事，先体检
```

`build_llm()` 会自动读取仓库根目录 `.env`。系统环境变量的优先级更高，因此 CI、
临时测试和部署环境仍可直接注入变量覆盖本地文件。`.env` 已被 Git 忽略，只有
`.env.example` 可以提交；修改 `.env` 后需要重启正在运行的 `server.py`。

**没配 key 系统照样跑**，自动退回离线桩，只是自述解析、命题、综合诊断走规则版。
所以接模型不是必需项，是增强项 —— 演示现场断网也不会挂。

体检脚本会逐项探明端点支持什么。不通过就别急着跑全流程：接模型最常见的三类
故障（JSON 模式不支持、模型名写错、限流），在全流程里表现出来**都是"生成结果
为空"**，极难定位。

## 二、固定双模型与自动降级

项目只启用阿里云百炼 OpenAI 兼容端点上的两个模型：

| 顺序 | 模型 | 用途 |
|---|---|---|
| 主模型 | `deepseek-v4-pro` | 命题 `make_item` 等高风险强任务 |
| 默认 / 降级模型 | `MiniMax-M3` | 其余任务，以及主模型失败后的接管 |

```dotenv
AGENTEDU_MODEL=MiniMax-M3
AGENTEDU_MODEL_STRONG=deepseek-v4-pro
```

强任务会先按 `AGENTEDU_RETRIES` 重试 DeepSeek；遇到限流、超时、服务端故障、
模型不可用或响应异常后，自动改用 MiniMax。`401` 表示同一把 API Key 无效，
切换模型没有意义，因此会直接失败并交给上层规则版兜底。MiniMax 自身失败时，
系统继续降级到固定题库、正则解析和规则诊断，整条流程不会中断。

冷启动阶段没有足够历史数据，路由只按任务类型排序：`make_item` 先用强模型，
其余任务先用默认模型。每个模型累计五个样本后，路由才允许动态重排；备选模型
成功率高出至少 20 个百分点时优先它，成功率接近且当前模型平均延迟达到备选模型
两倍时也切换。这个门槛避免一两次偶然失败或慢请求改变既定路由。

`llm.stats()` 会分别给出 `by_model` 和 `fallbacks`，用于证明真实调用分布和
自动降级次数。价格变化快，单价仍以百炼控制台为准。

## 三、额度与稳定性

### 三条额度保护（代码里已经做了）

免费档真正的约束不是"能不能用"，是**每分钟请求数**和**总额度**。
没有这三条，一次演示很容易把额度打光，而且失败方式很难看。

| 开关 | 作用 | 为什么需要 |
|---|---|---|
| `AGENTEDU_RPM` | 主动限速 | 免费档限 RPM，超了返 429。靠重试硬扛的话，一次测评几十次调用大部分时间耗在退避等待上，现场看着像卡死。主动限速比被动挨罚好。 |
| `AGENTEDU_BUDGET_CALLS` | 调用次数硬上限 | 额度悄悄耗尽后，系统会一路回退规则版 —— **"能跑但已降级"是最坏的一种故障**。设了上限就在到顶前主动停用，并在 `stats()` 里标出 `budget_hit`。 |
| `AGENTEDU_CACHE` | 相同请求复用 | 系统提示词固定不变，评测批次里同一知识点会被反复起草，命中率可观。默认开启。 |

**额度用完不会崩。** 命题环节会捕获模型故障、返回 None、回退固定题库；
自述解析回退正则规则；综合诊断回退规则拼句。整条链路照样跑完，
只是那几处降级。演示现场额度用完还能继续演，和当场白屏，是两回事 ——
这条有测试盯着（`test_item_generation_degrades_instead_of_crashing`）。

一次 HTTP 尝试（包括失败、重试和降级前的尝试）都会消耗
`AGENTEDU_BUDGET_CALLS`，因此预算上限保护的是实际供应商调用次数，而不是仅保护
成功响应数。设置额度前先为失败重试留出余量。

### 熔断与本地运维状态

连续三次可熔断故障会打开该模型的断路器，路由暂时跳过它；60 秒后路由只放行一次
half-open 探测。探测成功即恢复闭合，失败则重新计时。`401` 是终止性鉴权故障：
客户端既不重试也不切换模型，因为相同密钥无法靠路由修复。

启动本地服务后，使用下面命令查看路由策略、两个模型的健康、尝试次数、成功率、
平均延迟和自动降级次数：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/model-status
```

`/api/model-status` 只在本地服务中提供，只读且已脱敏。它不返回 API Key、
Authorization 请求头、提示词、端点 URL、请求体或模型响应。相关单元测试只使用
本地假端点和测试字符串，绝不读取真实密钥。

### 当前双模型的额度配置

```dotenv
AGENTEDU_MODEL=MiniMax-M3
AGENTEDU_MODEL_STRONG=deepseek-v4-pro
AGENTEDU_RPM=10
AGENTEDU_BUDGET_CALLS=200
```

命题通过率低不影响演示完整性 —— 系统会回退到 47 道固定题库，
自适应测评、辩论、审核、资源生成全部照常。**免费档拿不下的只有"现场出变种题"
这一个增强点**，其余全都在。

## 四、省钱的几个点

- **批量调用**：多数平台的 batch 接口是实时价的五折，跑评测批次时用得上。
- **上下文缓存**：系统提示词固定不变，命中缓存后输入侧便宜一个数量级。
  本项目的提示词天然固定，收益明显。
- **错峰**：有的平台高峰时段加价，跑批量评测挪到夜里。
- **别拿旗舰模型写叙述**：`synthesize` 和 `diagnose_narrative` 加起来
  占调用量的大头，但对模型能力要求最低。

## 五、客户端已经处理掉的坑

`core/llm.py` 里的 `RealLLM` 不是最小实现，它处理了四件接真模型一定会遇到的事：

**重试。** 429 限流和 5xx 是常态不是异常。一次测评几十次调用，
没有指数退避的话中途断掉整条链路就废了。401 不重试也不切模型，
因为同一把 key 的鉴权失败无法靠降级修复。

**JSON 模式降级。** `response_format: {"type":"json_object"}` 是 OpenAI 的约定，
兼容接口不一定支持，不支持时直接报 400。客户端会自动降级：去掉该字段，
改在提示词里要求只输出 JSON，重试一次。**降级过一次就记住**，
后续不再白试，省掉一半的无效请求。

**按任务路由与自动降级。** 强任务优先 DeepSeek，失败后切到 MiniMax；
其余任务直接使用 MiniMax。

**用量与成本统计。** 不统计就不知道一次演示花多少钱，报告里也没法写成本。
`llm.stats()` 给出分任务、分模型的 token 数、降级次数和折算金额。

这些行为都有测试盯着（`tests/test_llm_client.py`，用本地假端点，不联网）。

## 六、接上之后哪些地方会变

| 环节 | 离线（无 key） | 接模型后 |
|---|---|---|
| 自述解析 | 正则规则抽取 | 模型抽取 + 规则校验兜底 |
| 命题 | 不可用，只用固定题库 | 现场出变种题，过四关审核 |
| 断言起草 | 按句切分知识库原文 | 生成式改写，仍需过审 |
| 综合诊断 | 规则拼句 | 模型归纳，数字仍由规则算 |
| 审核 / 辩论 / BKT / 选题 | **完全一致** | **完全一致** |

最后一行是重点：**判断逻辑不因为接了模型而改变**。模型负责产出内容，
规则负责把关和计算。这条边界是整个方案可信度的来源，接模型时不要越界。

`showcase.html` 双击打开时永远是离线模式（浏览器里没有 key，也不该有），
演示时要说清楚这个区别。

## 七、接上后必须重跑

```bash
python3 -m evalkit.redteam                       # 幻觉分类检出率
AGENTEDU_INJECT=0 python3 -m evalkit.run_eval --n 50
python3 -m evalkit.itemreport                    # 题目质量
```

现有的跑分都是离线桩产出的。真模型的幻觉形态比桩里注入的四类丰富得多，
审核规则大概率还要再补。README 里"共识分层相差 34 倍"那个结论
**必须用真模型重测**，不要直接拿去答辩。
