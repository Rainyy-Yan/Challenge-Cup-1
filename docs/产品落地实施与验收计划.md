# 产品落地实施与验收计划

> 状态：执行基线；总负责人：肖云涵。
> 本计划把可运行研究原型收敛为可复验的产品候选。计划、模板和工作稿不是完成证据；未实际形成的 PPT、视频、盖章报名表、外部提交回执和正式 scorecard 均保持未完成状态。

## 三类读者的交接入口

- **开发者**：保持现有在线闭环可运行，按 [README](../README.md) 完成部署与回归；不得把内部规则评测说成独立正式指标。
- **验收负责人**：按本计划的 M0–M6、G0–G4、UAT 和回滚规则收集证据；对每次变更建立新的候选 SHA 和冻结数据，不覆盖历史材料。
- **评审者**：从[官方任务书落地矩阵](官方任务书落地矩阵.md)核对官方条款、责任与缺口，从[官方指标数学口径与验收](官方指标数学口径与验收.md)复算 G2 指标，并仅把已实际登记的外部材料视为事实。

## 范围、依赖与关键路径

本阶段交付工业机器人领域的多智能体学习闭环、部署说明、单元测试、证据矩阵和正式指标复算通道。它不新增第二领域、生产鉴权、数据库、多租户或移动端；也不将内部“300+ 知识点”“CI 盲评”等加强目标冒充官方明确条款。

关键路径为：

```text
M0 要求/口径冻结 -> M1 工具可运行 -> M2 独立盲评包 -> M3 正式指标冻结
-> M4 材料一致化 -> M5 候选包复验 -> M6 只提交不开发
```

M2 的两名独立领域评分者和 M3 的第三位仲裁者是外部人工依赖；M5 的报名表、M6 的报名/邮件/云盘回执也是外部依赖。系统和开发者可验证格式、计算和文件哈希，但**不得**替代评分者、来源复核者、仲裁者、签字人、报名系统或赛事方。独立角色均从 `unassigned` 开始，须由肖云涵实际指定并保留授权/回避记录。

## UAT 用例与验收记录

每次候选包复验都记录执行人、日期、候选 SHA、环境、输入、预期、实际、截图/日志路径和结论。

| 用例 | 操作 | 预期与证据 |
|---|---|---|
| UAT-01 清洁启动 | 按 README 配置或清空 API key 后启动 `server.py`，打开 `http://127.0.0.1:8000`。 | 首页可访问，离线桩可保持闭环；记录启动日志。 |
| UAT-02 三类画像 | 依次选择三份合成画像，完成诊断和资源生成。 | 每个画像均显示个性化路径、三类资源和决策可视化；保存三次记录。 |
| UAT-03 反馈再生成 | 在任一画像完成一次学习反馈后继续流程。 | 系统展示反馈后的决策理由及更新资源；保存前后对照。 |
| UAT-04 回归 | 运行 Python、前端、评分器和证据索引的约定测试。 | 测试日志退出 0；失败不进入 G3/G4。 |
| UAT-05 模板错误路径 | 使用空模板运行 `formal_scorecard`。 | 退出码为 2，生成 JSON/Markdown，状态为 `not_assessable`；不登记为正式成绩。 |
| UAT-06 正式复算 | 仅在实际存在的冻结真值上运行 scorecard。 | 两份报告、哈希和退出码与 M3 记录一致；无真值则本项未完成。 |

## 回滚和异常规则

1. G1 回归、UAT 或部署失败：停止进入后续门禁，回退到最近一个已通过 UAT 的候选 SHA；将失败日志链接到决策记录，不删除失败证据。
2. G2 输入、盲化、签字、仲裁、Kappa 或样本门禁失败：保持 `not_assessable`，不修改旧冻结文件；建立新 dataset ID，重新盲评和仲裁。
3. G2 指标为 `fail`：保留 scorecard 与事实数据；修复产品后新建候选 SHA 和完整新样本，不得仅替换不利记录或重跑直到通过。
4. G3 文档、PPT 或视频与 scorecard 不一致：冻结封包，回到 M3/M4；只允许用同一份实际批准的证据更新材料。
5. G4 外部提交、报名或盖章缺失：不伪造文件，不标记完成；在证据索引保留 `planned`、`missing` 或 `external` 语义，等待外部主体处理。

## 决策记录

- **ADR-001**：官方任务书是上位依据；300+ 知识点、CI、双人盲评和置信区间是内部加强措施。
- **ADR-002**：模型可以生成内容，确定性代码只计算、验证和渲染；代码不产生人工事实。
- **ADR-003**：正式三指标依赖冻结的独立人工真值；现有规则评测仅用于内部回归和诊断。
- **ADR-004**：断言/适配记录按 case-cluster Bootstrap 10,000 次计算不确定性，并使用 Wilson 与 Bootstrap 的保守包络。
- **ADR-005**：用保守区间边界而不是点估计作谬误率和适配率判定；覆盖率对冻结全集加权计算。
- **ADR-006**：PDF、PPT、视频、盖章报名表、报名/送达回执和正式批准 scorecard 在实际产生前均是外部缺口，不做完成性陈述。

## 最终验收清单

1. 从 G0 矩阵确认所有官方条款都有路径、证据、责任角色、门禁和真实状态。
2. 从 G1 UAT 确认清洁部署、三类画像和反馈再生成存在运行证据。
3. 从 G2 确认独立人工审阅/仲裁证据与签字真实存在，且可复算结果不是 `not_assessable`；仅在 `pass` 时说明该冻结数据的指标门禁通过。
4. 从 G3 确认实际存在的展示材料与唯一候选 SHA、scorecard 一致；不存在则明确未完成。
5. 从 G4 确认包、校验和、报名表和送达回执实际存在；赛事审核和结果继续按外部状态记录。
